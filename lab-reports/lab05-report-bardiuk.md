## Особистий внесок

Я зробив каталог товарів, відгуки, список бажань, завантаження картинок і другу версію API.

1. **Категорії й товари (моделі `Category`, `Product`, сервіс `services/catalog.py`).**
   - Категорії: список з кількістю товарів, створення, перейменування, видалення. Категорію з товарами видалити не можна (409).
   - Товари: повний набір методів.
     - `GET` — список і один товар;
     - `POST` — новий товар, 201 із заголовком `Location`;
     - `PUT` — повна заміна; `PATCH` — лише передані поля;
     - `DELETE` — видалення; товар із замовлення дає 409.
2. **Пошук і фільтри.**
   - Параметри: `q` (назва й опис, без урахування регістру), `category_id`, `min_price`/`max_price`, `featured`, `sort`, сторінки `page`/`size`.
   - `sort` приймає лише п'ять дозволених значень, тож у SQL-запит потрапляє тільки наш варіант сортування.
   - Символи `%` і `_` у пошуку шукаються як звичайні символи.
3. **Валідація товару.**
   - Назва від 3 символів, ціна — ціле число більше 0, опис до 1000 символів.
   - Картинка — `http(s)://` або точна адреса файлу, який видав наш сервер. Категорія має існувати.
   - Ціна `"100"` (рядок), `12.5` чи `true` дає 422: схема в строгому режимі не перетворює їх мовчки.
4. **Картинки (`services/media.py`).** `POST /products/{id}/image` приймає файл (multipart, поле `file`):
   - тип визначається за вмістом файлу бібліотекою Pillow (JPEG, PNG, WebP), а не за назвою;
   - більше 5 МБ — 413, не картинка — 415;
   - ім'я файлу генерує сервер (uuid);
   - стара картинка видаляється з диска при заміні чи видаленні товару.
5. **Відгуки:**
   - список про товар (сторінками);
   - один відгук на товар від користувача, другий дає 409;
   - змінити можна лише власний відгук, видалити — автор або адміністратор;
   - для модерації — усі відгуки з назвою товару.
6. **Список бажань:** `PUT` і `DELETE /users/me/wishlist/{id}`. Обидва ідемпотентні: повтор не дає помилки й не дублює запис. Видалений товар зникає зі списків сам (каскад у базі).
7. **API v2 (`routers/v2/products.py`).** Замість `category_id` товар містить об'єкт `category`, а ще `rating` (середня оцінка й кількість відгуків). Рейтинги для всієї сторінки рахуються одним запитом. v1 не змінилась.
8. **Демо-дані** каталогу й відгуків — ті самі, що й у Lab 04.
9. **Рев'ю:** перевірив і схвалив PR Назара за чеклістом QA: реєстрація (201, 409), вхід (401, 200), токен клієнта на адмінці (403), обмеження `size` (422), 405.

## Ендпоінти моєї частини

| Метод | Адреса | Доступ |
|---|---|---|
| GET / POST / PATCH / DELETE | `/api/v1/categories`, `/api/v1/categories/{id}` | читання — усі, зміни — адмін |
| GET / POST / PUT / PATCH / DELETE | `/api/v1/products`, `/api/v1/products/{id}` | читання — усі, зміни — адмін |
| POST / DELETE | `/api/v1/products/{id}/image` | адмін |
| GET / POST | `/api/v1/products/{id}/reviews` | читання — усі, відгук — вхід |
| PATCH / DELETE | `/api/v1/reviews/{id}` | автор (видалити — ще й адмін) |
| GET | `/api/v1/admin/reviews` | адмін |
| GET / PUT / DELETE | `/api/v1/users/me/wishlist`, `…/{product_id}` | вхід |
| GET | `/api/v2/products`, `/api/v2/products/{id}` | усі |

## Технічні рішення

- **v2 як окрема версія.** Заміна поля `category_id` на об'єкт `category` зламала б клієнтів, які вже читають `category_id`. Тому v1 лишилась як була, а новий формат живе за адресою `/api/v2`. Обидві версії використовують той самий сервіс і ті самі фільтри.
- **Тип файлу за вмістом.** Назву `photo.png` і заголовок `Content-Type: image/png` може надіслати будь-хто. Pillow відкриває сам файл, тож текстовий файл із назвою `.png` не пройде.
- **Точна адреса картинки.** Поле `image_url` приймає лише адресу, яку видав наш сервер (`/media/products/<32 символи>.png`). Інакше адміністратор міг би вписати адресу чужого файлу, і той видалився б разом із «своїм» товаром.
- **PUT для списку бажань.** «Покласти товар у список» має однаковий результат, скільки разів не повтори. Це ідемпотентна дія, тому PUT, а не POST.
- **Як QA** я для кожного ендпоінта перевіряв не лише успіх, а й кожну можливу помилку:
  - чужий відгук (403), другий відгук (409);
  - неіснуючий товар (404), неправильні типи (422);
  - завеликий файл (413).

## Висновки

Пошук і сторінки в SQL, а не в Python, означають, що сервер віддає рівно одну сторінку, скільки б товарів не було. Окрема версія API показала, як змінювати формат даних, не ламаючи тих, хто вже ним користується. А завантаження файлів навчило не довіряти нічому, що надсилає клієнт, навіть назві файлу.
